Core features

Huno wraps any model with project context, memory, tools, and a permission system that asks before it acts.

Project Understanding

Scans your repository and produces a real project summary — frameworks, languages, structure, API routes, database models, build scripts and important files.

huno ask Answer

Project Q&A

Ask questions the way you think, not the way a search engine wants. Huno answers using your actual files and shows you the context it used.

huno remember Remember

Project Memory

Store decisions like "we use JWT auth for backend sessions" in .huno/memory.md and recall them later with huno recall.

huno audit Inspect

Project Audit

Checks architecture, code quality, security, docs, testing, performance, dependencies and env setup — with high, medium and low priority findings.

huno doc Document

Documentation Generation

Generate or refresh READMEs, API docs, architecture overviews, setup guides and changelogs. Kill documentation rot for good.

write_file Edit

Code Editing

Memory system

Your project's second brain.

Everything lives locally in your project's .huno/ directory — nothing leaves your machine except the prompts sent to whichever model you chose.

  • Project memory — decisions and conventions you save with huno remember, searched with huno recall.
  • Project map — a cached scan of your stack, structure, and important files.
  • Session history — recent conversation turns, so context survives between REPL sessions.

Permission & safety model

Safe by default. In control by design.

Huno never silently performs risky actions. It shows what it wants to read, edit, run — and the risk involved.

Safe without approval

Read files, list directories, search code, read git status and project config.

Requires approval

Write files, patch files, run shell commands — install, push, and deploy commands are flagged medium risk.

High-risk: explicit confirm

Commands matching delete, drop, rm, or docker compose down — shown in red before you can approve them.

huno — approval
Huno wants to run:

  docker compose down -v

Risk: This may delete local database volumes.

Approve? [y/N]
  • Show commands before running them
  • Show file changes before applying them
  • Show diffs after editing
  • Keep history logs
  • Support undo where possible
  • Never hide destructive operations
