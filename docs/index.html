Core features

More than a chatbot.
A developer harness.

Huno wraps any model with project context, memory, tools, permissions and workflows.

huno explain Understand

Project Understanding

Scans your repository and produces a real project summary — frameworks, languages, structure, API routes, database models, build scripts and important files.

huno ask Answer

Project Q&A

Ask questions the way you think, not the way a search engine wants. Huno answers using your actual files and shows you the context it used.

huno remember Remember

Project Memory

Store decisions like "we use JWT auth for backend sessions" in .huno/memory.md and recall them later with huno recall.

huno audit Inspect

Project Audit

Checks architecture, code quality, security, docs, testing, performance, dependencies and env setup — with high, medium and low priority findings.

huno doc Document

Documentation Generation

Generate or refresh READMEs, API docs, architecture overviews, setup guides and changelogs. Kill documentation rot for good.

huno run Execute

Safe Terminal Execution

Translate natural language into commands — with approval prompts, risk warnings and full history. You stay in control.

huno fix Edit

Code Editing

Plan, propose, and apply code changes with your approval. Huno shows a diff, runs validation, and summarizes what changed.

Multi-Agent Workflows

Manager, research, developer, reviewer and tester agents collaborate on larger tasks with shared memory and task logs.

Memory system

Your project's second brain.

Huno builds knowledge in three layers, stored locally in your .huno directory. The project remembers what the developer would otherwise forget.

  • Global memory — your preferences across every project.
  • Project memory — decisions, conventions and why-things-are-the-way-they-are.
  • Session memory — temporary context for the task at hand.

Permission & safety model

Safe by default. In control by design.

Huno never silently performs risky actions. It shows what it wants to read, edit, run — and the risk involved.

✅ Safe without approval

Read files, list directories, search code, read git status and project config.

⚠️ Requires approval

Write files, run shell commands, install dependencies, create migrations, run Docker commands.

🛑 High-risk: explicit confirm

Delete files or volumes, rewrite git history, push to remote, or touch production config.

huno — approval
Huno wants to run:

  docker compose down -v

Risk: This may delete local database volumes.

Approve? [y/N]
  • Show commands before running them
  • Show file changes before applying them
  • Show diffs after editing
  • Keep history logs
  • Support undo where possible
  • Never hide destructive operations
